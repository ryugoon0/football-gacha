# 기간제 「라이브」 카드 설계 (2026-09-06 초안)

`docs/CARD_GRADES_PLAN.md` 0절의 결정을 구체화한다: 「라이브」는 등급이 아니라 **기간제 컨셉 카드의 유형**이다.
그 주·그 달에 특별한 활약을 한 선수를 그 활약 기준 능력치로 내고, 정해진 기간에만 스카우트에서 나온다.

## 1. 개념

| 항목 | 내용 |
| --- | --- |
| 무엇 | 실제 경기에서 그 주(또는 그 달) 눈에 띈 선수의 **컨셉 카드**. 예: 「2026년 9월 2주 — 해트트릭」 |
| 등급 | 내부 타입 `Live` 재사용(레벨 상한 10, 훈련 비용표 동일). 수준은 플래티넘급이지만 그 주 활약만큼 종합을 얹는다(정규 카드 +2~+6, 상한 89) |
| 표시 | 카드 얼굴은 그대로(마크 추가 없음 — 사용자 결정). 상세 화면에 「라이브 · 2026년 9월 2주 · 활약 요약」 칩과 문장 |
| 기간 | `from`~`to`(KST). 기간 안에만 뽑기 풀에 들어가고, 기간이 지나면 풀에서 빠지되 보유 카드는 남는다 |
| 중복 | 같은 선수의 정규 카드·월드 카드와 공존(허용됨). 같은 선수 라이브 카드는 주마다 다른 카드 |
| 픽업 | 「이번 주 픽업」 자리를 라이브 카드로 대체: 라이브 기간 중에는 같은 등급이 나올 때 절반이 라이브 카드 |

## 2. 데이터

```
data/live/2026-W37.json
{
  "kind": "live",
  "label": "2026년 9월 2주",
  "from": "2026-09-07T00:00:00+09:00",
  "to":   "2026-09-13T23:59:59+09:00",
  "players": [
    { "key": "live-2637-01", "name": "<가명>", "real": "<실명>", "realClub": "...", "club": "<가명 클럽>",
      "pos": "ST", "nation": "...", "birthYear": 1998, "ovr": 88,
      "story": "9/6 홈 경기 해트트릭 · 도움 1",
      "stats": { "sho": 92, "pac": 90 }, "hidden": { "clutch": 10, "bigMatch": 10 } }
  ]
}
```

- 빌드(`scripts/build-squad-cards.mjs`)가 `data/live/*.json` 을 읽어 `SQUAD_ROSTER.Live` 뒤에 붙인다.
  extras: `{ squad: true, season: label, live: { from, to }, story }`. id 는 파일·항목 순서라 새 주 파일은 항상 새 파일로 추가.
- `PlayerDef.live?: { from: string; to: string; story: string }` 추가.
- 가명 규칙·실명 힌트는 스쿼드와 같다(`SQUAD_REAL_HINTS` 에 "실명 (클럽, 2026년 9월 2주 라이브)").
- 명단은 서버 번들에 들어가므로 **커밋·배포가 곧 발행**이다(스쿼드와 같은 경로, CI 가 함수 재배포).

## 3. 풀 포함 규칙

- `PLAYERS_BY_RARITY` 는 정적이라 그대로 두고, 뽑기 쪽 `releasedPoolFor(rarity, nowMs)` 가 `live` 카드를 **기간 안에서만** 포함한다.
  클라이언트 미리보기와 서버(draw-pack)가 같은 함수를 쓰며, 시각은 `pickupWeekKey` 처럼 KST 고정 오프셋으로 계산해 기기 시계
  차이로 갈리지 않게 한다. 서버는 `Date.now()` 를 쓰므로 조작 불가.
- 기간이 끝난 라이브 카드: 뽑기·조각 교환·합성 결과 풀에서 빠진다. 보유·경기 사용·훈련은 그대로.
- 픽업: `featuredPlayer(weekKey)` 를 "이번 주 라이브 카드 중 하나(없으면 기존 규칙)"로 바꾼다.

## 4. 화면

- 스카우트 탭 상단 「이번 주 라이브」 띠: 카드 1~3장, 남은 기간, 활약 한 줄. 카드를 누르면 상세.
- 상세(PlayerStatsModal·PlayerDetailModal·도감): 시즌 칩 자리에 「라이브 · 2026년 9월 2주」, 아래에 `story`.
- 선수관리 필터에 「라이브」 유형 필터 추가(등급 필터와 별개).
- 카드 얼굴은 변경 없음. 등급 글자 줄은 「플래티넘 · 클럽」 그대로인지, 라이브만 「라이브 · 클럽」으로 바꿀지 **결정 필요**
  (마크 추가는 아니고 같은 글자 줄의 문구 변경).

## 5. 운영 절차 (주간)

1. 월요일(KST) 운영자가 지난 주 활약 선수 1~3명을 고른다(실제 경기 결과 기준).
2. `data/live/<주>.json` 작성 → `node scripts/build-squad-cards.mjs` → 커밋·푸시 → CI 배포.
3. 패치 노트 「이번 주 라이브 카드」 자동 문구(빌드가 라벨·선수 수를 채움).
4. 기간이 끝나면 아무 조치 없이 풀에서 빠진다.
- 추후: 운영자 콘솔에서 JSON 을 만들어 커밋까지 하는 도구(GitHub API)로 줄일 수 있다.

## 6. 구현 순서와 규모

| 단계 | 내용 | 규모 |
| --- | --- | --- |
| ① | 빌드 스크립트 `data/live` 지원, `PlayerDef.live`, 실명 힌트 | 작음 |
| ② | 기간 필터 `releasedPoolFor(rarity, nowMs)`·픽업 대체, draw-pack 에 now 전달, 테스트 | 중간 |
| ③ | 스카우트 「이번 주 라이브」 띠, 상세 칩·story, 선수관리 필터 | 중간 |
| ④ | 첫 발행 1주분 데이터(실제 지난 주 활약 기준) + 패치 노트 | 작음 |

## 7. 결정 필요

- 발행 주기: 주간(권장) vs 월간, 장수 1~3.
- 카드 얼굴 등급 글자 줄을 라이브만 「라이브」로 바꿀지.
- 종합 보정 폭(+2~+6, 상한 89)과 라이브 카드 방출가(플래티넘과 동일 제안).
