# 앨범(카드 도감) 보상 — 검토안 (2026-09-06)

로드맵 7항의 「앨범/TP/서브팀컬러·케미」 중 앨범만 먼저 검토한 것이다. 사용자 결정 전
초안이며 코드는 아직 없다.

## 왜 지금인가

- 8개 리그 144클럽의 실제 스쿼드 카드 3,576장이 들어와 "클럽 하나를 모은다"는 목표가
  생겼다. 그 전에는 생성 명단이라 모을 이유가 약했다.
- 스카우트 확률과 방출 가격을 내린 뒤라, 중복 카드와 하위 등급 카드가 손에 남는다.
  앨범은 그 카드에 "등록하면 보상"이라는 두 번째 쓸모를 준다.
- 선수 도감(`PlayerArchiveModal`)은 이미 전 카드를 보여 준다. 앨범은 그 위에 "내가
  가진/등록한 카드"와 "묶음 완성 보상"만 얹으면 된다.

## 제안 — 세 층

| 층 | 묶음 | 완성 조건 | 보상(초안) |
| --- | --- | --- | --- |
| 클럽 | 클럽 한 팀의 현 시즌 카드 | 그 클럽 카드 11장 이상 등록 | 골드 + 그 클럽 팀 컬러 카드 1장(골드 이상) |
| 리그 | 리그 안 모든 클럽 앨범 완성 | 리그 20클럽(코리아 12) 전부 | 프리미엄 스카우트 티켓 3장 + 칭호 |
| 특별 | 월드 1차 배치, 리미티드 1주차 등 | 배치의 전 카드 | 월드 확정권 1장(운영자가 배치별로 정함) |

- **등록은 카드를 소모하지 않는다.** 보유 여부만 본다(등록 = 소유 기록). 카드를 팔면
  등록도 풀린다. 이렇게 하면 앨범 때문에 스쿼드 카드를 못 파는 갈등이 없다.
  (대안: 등록하면 카드가 앨범에 봉인되는 방식 — 중복 카드 소비를 유도하지만 규칙이
  복잡해진다. 초안은 비소모.)
- **보상은 한 번.** 묶음별 `claimed_at`을 서버에 둔다(`album_claims(user_id, set_id)`).
  클라이언트 세이브에 두면 지급이 조작될 수 있어 서버 기록 + 선물함 지급으로 한다.
- **진행률은 세이브에서 계산.** 카드 목록이 세이브에 있으니 완성 여부는 클라이언트가
  계산해 보여 주고, 수령 요청 때 서버가 `saves.data.cards`로 다시 검증한다(성적/선언
  분류상 "선언"이라 서버 재검증이 필요).

## 화면

- 「선수관리」 탭에 「앨범」 하위 탭. 리그 → 클럽 격자, 클럽 칸에 `등록 n/전체`와 진행 바.
- 클럽을 열면 스쿼드 카드가 실루엣(미보유)·컬러(보유)로 보이고, 완성 시 「보상 받기」.
- 완성 보상은 선물함 팝업으로 온다(기존 `GiftArrivalPopup`).

## 규모와 순서

1. 데이터: `lib/album.ts`에 묶음 정의(클럽 = `SQUAD_CLUBS`에서 자동, 특별 = 수기).
2. 서버: `album_claims` 테이블 + `claim_album_set(set_id)` RPC(세이브 재검증 → 선물 발송).
3. 화면: 앨범 탭, 클럽 상세, 보상 버튼.
4. 노브: 클럽 완성 골드, 리그 완성 티켓 수.

중간 규모(2~3일 분량). 케미·서브팀컬러는 경기 엔진을 건드려 별도 건이다.

## 결정이 필요한 것

- 등록 비소모(초안) vs 소모.
- 클럽 완성 기준: 11장(초안) / 전원(23~28장) / 비율(70%).
- 보상 종류: 골드만 / 골드+팀 컬러 카드 / 티켓 포함.
- 특별 묶음(월드·리미티드)에 보상을 붙일지, 붙이면 확정권을 낼지.
